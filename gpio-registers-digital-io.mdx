A button reads as pressed when nobody touched it. A new line of code for one LED switches off another. On the ATmega328P the cause is nearly always one wrong bit in one of the three registers that control each pin. This lesson explains what each register is for and how to change one bit without disturbing the others. You wire four LEDs and a push button, then write an electronic dice, with no `digitalRead()` and no `digitalWrite()`. #GPIO #BitManipulation #AVR

## GPIO Register Overview

<InArticleAd />


A general purpose input/output (GPIO) pin does one of two opposite jobs: it drives a voltage out, to light an LED, or it listens to a voltage that something outside puts on it, such as a button. So the chip holds three facts about each pin, each in a register, a byte whose 8 bits are wired to hardware. Think of two switches and a lamp per pin: one switch chooses the job, one chooses the level, and the lamp shows the level really on the wire.

| Register | You | What its bit means |
|----------|-----|---------|
| DDRx (data direction) | write | Which job the pin does: 1 = output, 0 = input |
| PORTx (port data) | write | Output pin: 1 = drive high (5 V), 0 = drive low (0 V). Input pin: 1 = pull-up on |
| PINx (port input) | read | The level that is really on the pin now |

The x is the port letter. The 23 I/O pins form Port B (PB0 to PB7), Port C (PC0 to PC6) and Port D (PD0 to PD7), each with its own three registers; bit 5 of DDRB, PORTB and PINB all belong to PB5. PORTx holds what you asked for, PINx what is on the wire, which on an input is decided by the circuit outside.

Together, the DDRx bit and the PORTx bit of a pin select one of four states:

| DDRx bit | PORTx bit | The pin is |
|------|-------|-------------------|
| 0 | 0 | Input, floating: connected to nothing inside the chip |
| 0 | 1 | Input with the internal pull-up resistor |
| 1 | 0 | Output, driven low |
| 1 | 1 | Output, driven high |

The pull-up is a resistor from the pin to the supply (VCC); the section on pull-up resistors shows why a button needs one.

```text
  Output                     Input with pull-up
  (DDRx bit = 1)             (DDRx = 0, PORTx = 1)

     VCC                        VCC
      |                          |
    [sw A]                      [R] inside the chip,
      |                          |  20K to 50K
      +-----> pin, to load       +-----< pin, from button
      |                          |
    [sw B]                    (button to GND)
      |
     GND

  PORTx bit = 1 closes sw A: pin high
  PORTx bit = 0 closes sw B: pin low
```

### Bit Manipulation Patterns

One register holds eight pins, so writing a whole number, such as `PORTD = 8`, sets one pin and forces the other seven to 0. These patterns change one bit and leave the rest:

- `(1 << PB5)` is the number 1 moved 5 places left: binary 00100000, a byte with only bit 5 set. It is called a mask.
- `|=` (OR) sets the bits of the mask to 1.
- `&= ~` (AND with the inverted mask) clears them to 0.
- `^=` (exclusive OR) inverts them.
- `&` in an `if` tests them.

For more on binary numbers and bitwise logic, see [Digital Electronics: Binary, Hex, and Number Systems](/education/digital-electronics/binary-hex-number-systems/).

```c
/* Set bit (make pin output or drive high) */
DDRB |= (1 << PB5);

/* Clear bit (make pin input or drive low) */
PORTB &= ~(1 << PB5);

/* Toggle bit */
PORTB ^= (1 << PB5);

/* Read a single bit */
if (PIND & (1 << PD6)) {
    /* PD6 is high */
}

/* Set multiple bits at once */
DDRD |= (1 << PD2) | (1 << PD3) | (1 << PD4) | (1 << PD5);
```

## Circuit Connections

<InArticleAd />


Each LED goes from its pin (PD2 to PD5) through a 220 ohm resistor to ground, longer leg (the anode) towards the pin. The resistor limits the current to 9 to 14 mA. A pin is tested for 20 mA in normal work; 40 mA is the absolute maximum, beyond which it can be damaged.

The push button connects PD6 to ground, and a 10K resistor pulls PD6 up to VCC, so the pin reads high when the button is free and low when it is pressed.

```text
          ATmega328P
         +-----------+
         |       PD6-+---+---[10K]---VCC
         |           |   |
         |           |  [BTN] (press = LOW)
         |           |   |
         |           |  GND
         |           |
         |      PD2--+--[220R]--[LED1]--GND
         |      PD3--+--[220R]--[LED2]--GND
         |      PD4--+--[220R]--[LED3]--GND
         |      PD5--+--[220R]--[LED4]--GND
         +-----+-----+
               |
              GND
```

You can leave out the external 10K resistor: the firmware also switches on the internal pull-up of PD6.

| Signal | Arduino Nano Pin | ATmega328P Pin | Connection |
|--------|-----------------|----------------|------------|
| LED 1 | D2 | PD2 | LED anode, 220R to GND |
| LED 2 | D3 | PD3 | LED anode, 220R to GND |
| LED 3 | D4 | PD4 | LED anode, 220R to GND |
| LED 4 | D5 | PD5 | LED anode, 220R to GND |
| Button | D6 | PD6 | Button to GND, 10K to VCC |

## The LFSR Random Number Generator

<InArticleAd />


A microcontroller does exactly what the program says, so it cannot throw a dice. It needs a rule that gives numbers which only look random. A linear feedback shift register (LFSR) is such a rule, with two cheap operations:

1. Shift the 16-bit number one place to the right.
2. If the bit that dropped off was 1, XOR the number with a fixed mask, `0xB400`.

This form is a Galois LFSR. With this mask the number passes through 65,535 values before the sequence repeats, always in the same order. The dice is unpredictable because the main loop steps the LFSR thousands of times a second, so the result depends on the instant you press.

```c
static uint16_t lfsr = 0xACE1;  /* Non-zero seed */

static uint8_t roll_dice(void)
{
    /* Galois LFSR step */
    uint8_t lsb = lfsr & 1;
    lfsr >>= 1;
    if (lsb) lfsr ^= 0xB400;  /* Taps at 16,14,13,11 */

    return (lfsr % 6) + 1;  /* Result: 1 to 6 */
}
```

## Dice LED Patterns

<InArticleAd />


Four LEDs cannot show six dots, so each dice value gets its own pattern, and 5 and 6 add blinks. Place the LEDs in a square: LED1 top left, LED2 top right, LED3 bottom left, LED4 bottom right.

| Dice Value | LED1 | LED2 | LED3 | LED4 | Pattern |
|-----------|------|------|------|------|---------|
| 1 | OFF | ON | OFF | OFF | One LED |
| 2 | ON | OFF | OFF | ON | Diagonal |
| 3 | ON | OFF | ON | ON | Triangle |
| 4 | ON | ON | ON | ON | All corners |
| 5 | ON | ON | ON | ON | All + single blink |
| 6 | ON | ON | ON | ON | All + double blink |

## Complete Firmware

<InArticleAd />


```c
#define F_CPU 16000000UL

#include <avr/io.h>
#include <util/delay.h>

/* Variable-length delay: _delay_ms() requires a compile-time
   constant on many avr-gcc versions, so we wrap it in a loop. */
static void delay_ms(uint16_t ms)
{
    while (ms--) _delay_ms(1);
}

#define LED_MASK ((1<<PD2)|(1<<PD3)|(1<<PD4)|(1<<PD5))
#define BTN_PIN  PD6

static uint16_t lfsr = 0xACE1;

static uint8_t roll_dice(void)
{
    uint8_t lsb = lfsr & 1;
    lfsr >>= 1;
    if (lsb) lfsr ^= 0xB400;
    return (lfsr % 6) + 1;
}

static void show_dice(uint8_t value)
{
    /* Clear all LEDs */
    PORTD &= ~LED_MASK;

    uint8_t pattern = 0;
    switch (value) {
        case 1: pattern = (1<<PD3); break;
        case 2: pattern = (1<<PD2)|(1<<PD5); break;
        case 3: pattern = (1<<PD2)|(1<<PD4)|(1<<PD5); break;
        case 4: pattern = (1<<PD2)|(1<<PD3)|(1<<PD4)|(1<<PD5); break;
        case 5: /* All + single blink to distinguish from 4 */
            pattern = (1<<PD2)|(1<<PD3)|(1<<PD4)|(1<<PD5);
            PORTD |= pattern;
            delay_ms(100);
            PORTD &= ~LED_MASK;
            delay_ms(100);
            break;
        case 6: /* All + double blink to distinguish from 4 and 5 */
            pattern = (1<<PD2)|(1<<PD3)|(1<<PD4)|(1<<PD5);
            PORTD |= pattern;
            delay_ms(100);
            PORTD &= ~LED_MASK;
            delay_ms(100);
            PORTD |= pattern;
            delay_ms(100);
            PORTD &= ~LED_MASK;
            delay_ms(100);
            break;
    }
    PORTD |= pattern;
}

static uint8_t button_pressed(void)
{
    /* The pin reads 0 while the button is pressed */
    if (!(PIND & (1 << BTN_PIN))) {
        _delay_ms(50);  /* Debounce */
        if (!(PIND & (1 << BTN_PIN))) {
            return 1;
        }
    }
    return 0;
}

int main(void)
{
    /* LEDs as outputs */
    DDRD |= LED_MASK;

    /* Button as input with internal pull-up */
    DDRD &= ~(1 << BTN_PIN);
    PORTD |= (1 << BTN_PIN);

    uint8_t last_value = 1;
    show_dice(last_value);

    while (1) {
        /* Keep the LFSR running for randomness */
        (void)roll_dice();

        if (button_pressed()) {
            /* Rolling animation */
            for (uint8_t i = 0; i < 10; i++) {
                show_dice((i % 6) + 1);
                delay_ms(50 + i * 20);
            }

            last_value = roll_dice();
            show_dice(last_value);

            /* Wait for button release */
            while (!(PIND & (1 << BTN_PIN)));
            _delay_ms(50);
        }
    }
}
```

## Compiling and Flashing

<InArticleAd />


Use the Makefile of the Morse beacon, replace `main.c` with the dice code, then:

```bash
make flash
```

Press the button. The LEDs run through a rolling animation and then stop on a dice value.

Where a delay is calculated while the program runs, such as `50 + i * 20`, the firmware calls its own `delay_ms()`. On many avr-gcc versions `_delay_ms()` accepts only a fixed number, so this wrapper calls `_delay_ms(1)` in a loop; the course uses it wherever a delay is a variable.

## Understanding Pull-Up Resistors

<InArticleAd />


An input pin holds no level by itself. Connected to nothing, it collects electrical noise and reads 0 or 1 at random: a floating input. A button that only connects the pin to ground has the same problem whenever it is not pressed.

```text
  Floating input:          Pull-up input:

     ???                       VCC
      |                         |
      | (noise couples in)     [R] 10K (ext) or
      |                         |  20-50K (int)
   +--+--+                  +--+--+
   | PINx | reads random    | PINx | reads HIGH
   +--+--+                  +--+--+
      |                         |
     (nothing)              [Switch]--GND
                            (press = LOW)
```

A pull-up resistor connects the pin to VCC, so a free button reads high. Pressing connects the pin straight to ground, a much stronger path than the resistor, so it reads low. (A pull-up is like a door spring: it closes the door when nobody holds it, and any hand is stronger.)

Each pin of the ATmega328P has an internal pull-up of 20K to 50K, switched on by writing 1 to the PORTx bit while the DDRx bit is 0. An external 10K pulls more strongly, which helps on long wires that collect noise.

## Exercises

<InArticleAd />


1. Modify the dice to support values 1 through 8 by adding unique blink patterns for 7 and 8 (for example, alternating flashes).
2. Replace the delay-based debounce with a state machine that samples the button every 5 ms and requires three consecutive identical readings before accepting a press.
3. Add a "cheat mode": if you hold the button for more than 2 seconds, always roll a 6.
4. Measure the current drawn by each LED with a multimeter. Verify it matches the calculation: $I = (5\,\text{V} - V_F) / 220\,\Omega$, where $V_F$ is the LED forward voltage. A red LED with $V_F \approx 2\,\text{V}$ gives $(5 - 2)/220 \approx 13.6\,\text{mA}$.

## Summary

<InArticleAd />


DDRx chooses the job of each pin, PORTx sets what an output drives or switches on a pull-up, and PINx reports the real level. A mask with `|=`, `&= ~` or `^=` changes one pin and leaves the other seven as they were. Every other register of the ATmega328P is changed the same way.
