You wire a new display, load the program, and the screen stays black, or fills with random dots. The cause is usually the clock setting of the bus, one control pin at the wrong level, or a missing command. This lesson covers SPI (Serial Peripheral Interface), the fast bus of displays, SD cards and many sensors, so that you can find each cause. You write a driver for the SSD1306 OLED display and build a clock on its 128x64 pixel screen. #SPI #OLED #SSD1306

## SPI Protocol Fundamentals

<InArticleAd />


A serial bus sends bits one after another on one wire, so the receiver must know where each bit begins. SPI adds a second wire, the clock: the sender puts a bit on the data wire, and one clock pulse tells the receiver "read it now".

The master, here the ATmega328P, makes the clock and starts every transfer. SPI has four signals: SCK (serial clock), MOSI (master out, slave in), MISO (master in, slave out) and SS (slave select, also called CS, chip select). The master holds SS low to tell one slave "this transfer is for you".

```text
  ATmega328P (Master)         SSD1306 OLED (Slave)
  +------------------+       +-------------------+
  |                  |       |                   |
  |  MOSI (PB3) -----+------>| DIN (data in)     |
  |                  |       |                   |
  |  MISO (PB4) <----+-------| (not used)        |
  |                  |       |                   |
  |  SCK  (PB5) -----+------>| CLK (clock)       |
  |                  |       |                   |
  |  SS   (PB2) -----+------>| CS  (chip select) |
  |                  |       |                   |
  +------------------+       +-------------------+
```

Each device holds an 8-bit shift register, eight cells in which the bits move one place on each clock pulse. On every pulse the master pushes one bit out on MOSI and takes one in from MISO, so after eight pulses the two have exchanged a byte: SPI always sends and receives together. This display has nothing to report, so its MISO wire is left out.

Several slaves can share SCK, MOSI and MISO, but each needs its own SS line. On the Arduino boards, MOSI is D11, MISO is D12, SCK is D13 and SS is D10. For a comparison with I2C and other buses, see [Digital Electronics: Bus Architecture and Interfaces](/education/digital-electronics/bus-architecture-interfaces/).

### Clock Polarity and Phase

A clock pulse has a rising edge (low to high) and a falling edge. The data wire changes on one edge and is read on the other, when it is steady, and master and slave must agree which is which; if not, the slave reads each bit while it changes, and every byte arrives wrong.

Two bits set the agreement: CPOL (clock polarity) is the level of the clock when nothing is sent, and CPHA (clock phase) chooses whether data is read on the first edge of a pulse or the second. That gives four SPI modes:

| SPI Mode | CPOL | CPHA | Clock Idle | Data Sampled On |
|----------|------|------|------------|-----------------|
| 0 | 0 | 0 | Low | Rising edge |
| 1 | 0 | 1 | Low | Falling edge |
| 2 | 1 | 0 | High | Falling edge |
| 3 | 1 | 1 | High | Rising edge |

The SSD1306 uses Mode 0 (CPOL=0, CPHA=0). The slave fixes the mode: read it in the datasheet of each device. One byte in Mode 0, with bit D7 first:

```text
  CS    ──┐                                   ┌──────
          └───────────────────────────────────┘

              ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐
  SCK   ──────┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └────────

            ┌───┬───┬───┬───┬───┬───┬───┬───┐
  MOSI  ────┤D7 │D6 │D5 │D4 │D3 │D2 │D1 │D0 ├────────
            └───┴───┴───┴───┴───┴───┴───┴───┘
        (data changes on falling edge,
         sampled on rising edge)

                                            ┌──────── set
  SPIF  ────────────────────────────────────┘
```

## SPI Register Configuration

<InArticleAd />


Three registers run the SPI hardware:

- SPCR (SPI Control Register) holds the settings: SPE switches the hardware on, MSTR makes the chip the master, and other bits set the mode and the clock speed.
- SPDR (SPI Data Register) is the shift register. Writing a byte to it starts the eight clock pulses.
- SPSR (SPI Status Register) holds SPIF, the flag that the hardware sets when the byte has gone, and a double-speed bit (SPI2X).

Set the SS pin (PB2) as an output before you enable master mode. If PB2 is an input and something pulls it low, the hardware clears MSTR and the chip stops being the master.

```c
static void spi_init(void)
{
    /* Set MOSI, SCK, SS as outputs */
    DDRB |= (1 << PB3) | (1 << PB5) | (1 << PB2);

    /* Enable SPI, Master mode, clock = F_CPU/4 (4 MHz) */
    SPCR = (1 << SPE) | (1 << MSTR);
    /* Mode 0 is default (CPOL=0, CPHA=0) */
}

static uint8_t spi_transfer(uint8_t data)
{
    SPDR = data;
    while (!(SPSR & (1 << SPIF)));  /* Wait for transfer complete */
    return SPDR;                    /* The byte that came in on MISO */
}
```

## SSD1306 OLED Wiring

<InArticleAd />


The 7-pin OLED module needs three bus wires (clock, data, chip select) and two that are not part of SPI: RES resets the display controller, and DC (data/command) says whether the next byte is a command or pixels.

| OLED Pin | Function | Arduino Nano Pin | ATmega328P Pin |
|----------|----------|-----------------|----------------|
| GND | Ground | GND | GND |
| VCC | Power (3.3V or 5V) | 5V | VCC |
| D0 (CLK) | SPI Clock | D13 | PB5 (SCK) |
| D1 (MOSI) | SPI Data | D11 | PB3 (MOSI) |
| RES | Reset | D8 | PB0 |
| DC | Data/Command | D9 | PB1 |
| CS | Chip Select | D10 | PB2 (SS) |

![Wiring drawing: Nano D13 to OLED clock, D11 to data, D8 to reset, D9 to DC, D10 to CS, plus 5V and GND.](https://cdn.siliconwit.com/education/embedded-programming-atmega328p/Nano-OLED-SPI.png)

The SSD1306 itself is a 3.3 V chip. Most modules carry a regulator, so 5 V on VCC is fine, but many connect D0, D1, RES, DC and CS straight to the controller. 5 V signals then work on most modules but are outside the SSD1306 data sheet; in a product, use a level shifter or run the microcontroller at 3.3 V.

## SSD1306 Driver

<InArticleAd />


The SSD1306, the controller chip on the display module, holds one bit of memory for each pixel, and you set pixels by writing bytes into that memory. One byte is not a row of 8 pixels, as you might expect, but a column of 8 pixels, so the screen is cut into 8 horizontal bands called pages, each 8 pixels tall and 128 bytes long.

```text
  128 columns
  <------------------------------>
  +-----+-----+-----+-- --+-----+ Page 0
  |byte0|byte1|byte2| ...  |b127 | (rows 0-7)
  +-----+-----+-----+-- --+-----+
  +-----+-----+-----+-- --+-----+ Page 1
  |b128 |b129 |b130 | ...  |b255 | (rows 8-15)
  +-----+-----+-----+-- --+-----+
   ...                             ...
  +-----+-----+-----+-- --+-----+ Page 7
  |b896 |b897 |b898 | ...  |b1023| (rows 56-63)
  +-----+-----+-----+-- --+-----+
```

In each byte, bit 0 is the top pixel and bit 7 is the bottom pixel. The whole screen is $128 \times 8 = 1024$ bytes.

The same data wire carries commands (settings such as contrast) and pixel data, which the display cannot tell apart from the bits. The D/C pin tells it: low for a command, high for pixel data. `oled_cmd()` and `oled_data()` differ only in that level.

`oled_init()` sends a list of commands from the SSD1306 datasheet. Remember only the charge pump (0x8D, 0x14), which makes the higher voltage the pixels need. A black screen with correct wiring is often a missing charge pump command.

```c
#define OLED_DC   PB1
#define OLED_RST  PB0
#define OLED_CS   PB2

static void oled_cmd(uint8_t cmd)
{
    PORTB &= ~(1 << OLED_DC);   /* Command mode */
    PORTB &= ~(1 << OLED_CS);   /* Select */
    spi_transfer(cmd);
    PORTB |= (1 << OLED_CS);    /* Deselect */
}

static void oled_data(const uint8_t *buf, uint16_t len)
{
    PORTB |= (1 << OLED_DC);    /* Data mode */
    PORTB &= ~(1 << OLED_CS);
    for (uint16_t i = 0; i < len; i++) {
        spi_transfer(buf[i]);
    }
    PORTB |= (1 << OLED_CS);
}

static void oled_init(void)
{
    /* Configure control pins */
    DDRB |= (1 << OLED_DC) | (1 << OLED_RST) | (1 << OLED_CS);

    /* Hardware reset */
    PORTB &= ~(1 << OLED_RST);
    _delay_ms(10);
    PORTB |= (1 << OLED_RST);
    _delay_ms(10);

    /* Initialization sequence */
    oled_cmd(0xAE);  /* Display off */
    oled_cmd(0xD5);  /* Set clock divide */
    oled_cmd(0x80);
    oled_cmd(0xA8);  /* Set multiplex ratio */
    oled_cmd(0x3F);  /* 64 rows */
    oled_cmd(0xD3);  /* Display offset */
    oled_cmd(0x00);
    oled_cmd(0x40);  /* Start line 0 */
    oled_cmd(0x8D);  /* Charge pump */
    oled_cmd(0x14);  /* Enable */
    oled_cmd(0x20);  /* Memory addressing mode */
    oled_cmd(0x00);  /* Horizontal */
    oled_cmd(0xA1);  /* Segment remap */
    oled_cmd(0xC8);  /* COM scan direction */
    oled_cmd(0xDA);  /* COM pins config */
    oled_cmd(0x12);
    oled_cmd(0x81);  /* Contrast */
    oled_cmd(0xCF);
    oled_cmd(0xD9);  /* Pre-charge period */
    oled_cmd(0xF1);
    oled_cmd(0xDB);  /* VCOMH deselect */
    oled_cmd(0x40);
    oled_cmd(0xA4);  /* Display from RAM */
    oled_cmd(0xA6);  /* Normal (not inverted) */
    oled_cmd(0xAF);  /* Display on */
}
```

## Framebuffer and Font Rendering

<InArticleAd />


The program cannot read the display memory back, so it cannot change one pixel and keep the others in the same byte. The answer is a framebuffer, a 1024-byte array in RAM with the layout of the display memory: the program draws into it, then sends all of it in one transfer, a flush. The array uses half of the chip's 2048 bytes of RAM.

Byte `page * 128 + col` of the array is column `col` of page `page`. A font character is 5 such bytes, one for each of its columns.

```c
static uint8_t framebuf[1024];

/* 5x7 font for digits '0'-'9' and ':' */
static const uint8_t font_5x7[][5] = {
    {0x3E,0x51,0x49,0x45,0x3E},  /* 0 */
    {0x00,0x42,0x7F,0x40,0x00},  /* 1 */
    {0x42,0x61,0x51,0x49,0x46},  /* 2 */
    {0x21,0x41,0x45,0x4B,0x31},  /* 3 */
    {0x18,0x14,0x12,0x7F,0x10},  /* 4 */
    {0x27,0x45,0x45,0x45,0x39},  /* 5 */
    {0x3C,0x4A,0x49,0x49,0x30},  /* 6 */
    {0x01,0x71,0x09,0x05,0x03},  /* 7 */
    {0x36,0x49,0x49,0x49,0x36},  /* 8 */
    {0x06,0x49,0x49,0x29,0x1E},  /* 9 */
    {0x00,0x36,0x36,0x00,0x00},  /* : */
};

static void fb_clear(void)
{
    for (uint16_t i = 0; i < 1024; i++) framebuf[i] = 0;
}

static void fb_draw_char(uint8_t col, uint8_t page, char c)
{
    uint8_t idx;
    if (c >= '0' && c <= '9') idx = c - '0';
    else if (c == ':') idx = 10;
    else return;

    uint16_t offset = page * 128 + col;
    for (uint8_t i = 0; i < 5; i++) {
        if (offset + i < 1024) {
            framebuf[offset + i] = font_5x7[idx][i];
        }
    }
}

static void fb_draw_string(uint8_t col, uint8_t page, const char *s)
{
    while (*s) {
        fb_draw_char(col, page, *s++);
        col += 6;  /* 5 pixels + 1 space */
    }
}

static void oled_flush(void)
{
    oled_cmd(0x21); oled_cmd(0); oled_cmd(127);  /* Column range */
    oled_cmd(0x22); oled_cmd(0); oled_cmd(7);    /* Page range */
    oled_data(framebuf, 1024);
}
```

## Complete Firmware

<InArticleAd />


Timer1 raises an interrupt every millisecond, and its routine counts 1000 of them to make one second. `seconds` is a 32-bit variable, which this 8-bit processor reads one byte at a time, so `ATOMIC_BLOCK` switches interrupts off during the read; without it, an interrupt in the middle of the read could give a mixed value.

```c
#define F_CPU 16000000UL

#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/delay.h>
#include <util/atomic.h>

/* Include all the SPI, OLED, and font code from above */

volatile uint32_t seconds = 0;

ISR(TIMER1_COMPA_vect)
{
    static uint16_t subsec = 0;
    subsec++;
    if (subsec >= 1000) {
        subsec = 0;
        seconds++;
    }
}

static void timer1_init(void)
{
    TCCR1A = 0;
    TCCR1B = (1 << WGM12) | (1 << CS11) | (1 << CS10);
    OCR1A  = 249;  /* 1 ms tick */
    TIMSK1 = (1 << OCIE1A);
}

static void format_time(uint32_t sec, char *buf)
{
    uint8_t h = (sec / 3600) % 24;
    uint8_t m = (sec / 60) % 60;
    uint8_t s = sec % 60;

    buf[0] = '0' + h / 10;
    buf[1] = '0' + h % 10;
    buf[2] = ':';
    buf[3] = '0' + m / 10;
    buf[4] = '0' + m % 10;
    buf[5] = ':';
    buf[6] = '0' + s / 10;
    buf[7] = '0' + s % 10;
    buf[8] = '\0';
}

int main(void)
{
    spi_init();
    oled_init();
    timer1_init();
    sei();

    uint32_t last_sec = 0xFFFFFFFF;

    while (1) {
        uint32_t now;
        ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
            now = seconds;
        }

        if (now != last_sec) {
            last_sec = now;
            char time_str[9];
            format_time(now, time_str);

            fb_clear();
            fb_draw_string(40, 3, time_str);  /* Centered on page 3 */
            oled_flush();
        }
    }
}
```

### Check it

The time must appear mid-screen, `00:00:00` at power-on, changing once a second (a simulation, with the SPI bytes rebuilt into a picture, showed `00:00:02` in pixel rows 24 to 31 after two seconds). Then compare it with a phone clock for one hour:

- On a Nano with a 16 MHz crystal (about 50 ppm), it drifts at most about 0.2 s an hour, 4 s a day.
- On an Uno, whose ATmega328P runs from a ceramic resonator (up to 0.5 %), it can drift 18 s an hour, 7 minutes a day.
- At every power cut it starts again at `00:00:00`.

This is why a clock that must be right uses a separate real-time clock chip, such as the DS3231, with its own crystal and a coin cell. To test the change of day without waiting 24 hours, start `seconds` at 86390 for one run: ten seconds later `23:59:59` must become `00:00:00`.

## SPI Clock Speed and Prescaler

<InArticleAd />


Every slave has a highest clock it can follow, and long wires lower it. The SPI clock is the system clock divided by a number set with SPI2X in SPSR and SPR1/SPR0 in SPCR.

The SSD1306 accepts up to about 10 MHz, so the default F_CPU/4 (4 MHz) is safe. One byte then takes $8 / 4\,\text{MHz} = 2$ microseconds, and the 1024 bytes of the screen at least 2 milliseconds. For faster transfers, enable SPI2X for F_CPU/2 (8 MHz).

| SPI2X | SPR1 | SPR0 | Clock Divider | Speed (16 MHz) |
|-------|------|------|---------------|----------------|
| 0 | 0 | 0 | /4 | 4 MHz |
| 0 | 0 | 1 | /16 | 1 MHz |
| 0 | 1 | 0 | /64 | 250 kHz |
| 0 | 1 | 1 | /128 | 125 kHz |
| 1 | 0 | 0 | /2 | 8 MHz |
| 1 | 0 | 1 | /8 | 2 MHz |
| 1 | 1 | 0 | /32 | 500 kHz |
| 1 | 1 | 1 | /64 | 250 kHz |

## Summary

<InArticleAd />


SPI moves one bit on each clock pulse, in both directions together, to the slave whose select line is low. Master and slave must use the same mode: the idle level of the clock and the edge on which data is read. The SSD1306 needs one more pin, D/C, to tell commands from pixel data.
