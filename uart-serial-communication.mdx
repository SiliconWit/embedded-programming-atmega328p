A board with no screen cannot show you what it is doing: a wrong sensor reading stays hidden inside the chip, and you can only guess at the fault. A serial link solves this with two wires, on which the chip sends text to your computer one bit after another. You set up the serial hardware of the ATmega328P from its registers and learn why both ends must agree on the speed. The project is a temperature logger that sends one reading a second as a line of text. #UART #Serial #DataLogging

## What We Are Building

<Card title="Temperature Logger with CSV Export" icon="star">
A logger that reads an NTC thermistor, a resistor whose resistance falls as it gets warmer, once per second. The chip's analog to digital converter (ADC), which has its own lesson later, turns its voltage into a number from 0 to 1023. On the PC you save the lines to a file and plot them.

## USART Register Overview

<InArticleAd />


A UART (universal asynchronous receiver/transmitter) sends bits on one wire with no clock wire beside it, so the receiver cannot know when a byte begins or how long each bit lasts. The frame solves both:

- The wire rests high. Every byte begins with a start bit, which is low. Its falling edge tells the receiver that a byte begins.
- Both sides are set to the same speed in advance: the baud rate, in bits per second. From the start edge the receiver measures time with its own clock and reads each bit at the middle of its period.
- After the eight data bits, lowest bit (D0) first, comes a stop bit, which is high. It returns the wire to rest, so the next start edge can be seen.

This format is written 8N1: 8 data bits, no parity bit (an optional check bit), 1 stop bit.

```text
  The letter 'A' (0x41 = binary 01000001), D0 first:

  idle                                              idle
  ____     ___                     ___     ___________
      |   |   |                   |   |   |
      |___|   |___________________|   |___|
       St  D0  D1  D2  D3  D4  D5  D6  D7  Sp
       0   1   0   0   0   0   0   1   0   1

  St = start bit, Sp = stop bit
  At 9600 baud one bit lasts 1/9600 s = 104 us
  One byte needs 10 bits = 1.04 ms
```

In the ATmega328P this hardware is called USART0. The S stands for a synchronous mode with a clock wire, which this lesson does not use. Five registers control it:

| Register | Purpose |
|----------|---------|
| UDR0 | The data: write a byte here to send it, read here to get a received byte |
| UCSR0A | Status flags. UDRE0 = ready for the next byte to send. RXC0 = a byte has arrived |
| UCSR0B | Switches: TXEN0 and RXEN0 turn on the transmitter and the receiver. The bits ending in IE turn on interrupts |
| UCSR0C | Frame format: number of data bits (UCSZ), parity (UPM), stop bits (USBS) |
| UBRR0H/L | Baud rate, a 12-bit number in two bytes |

### Baud Rate Calculation

The chip makes its bit timing by dividing the system clock by a whole number that you write into UBRR. In normal speed mode (bit U2X0 = 0), where $F_{\text{CPU}}$ is the clock in hertz and BAUD is the speed you want:

$$
\text{UBRR} = \frac{F_{\text{CPU}}}{16 \times \text{BAUD}} - 1
$$

For 16 MHz and 9600 baud: $\text{UBRR} = 16\,000\,000 / (16 \times 9600) - 1 = 103.17$. The register holds only whole numbers, so you write 103, and the real speed is $16\,000\,000 / (16 \times 104) = 9615$ baud. That is 0.16% too fast.

A small error is harmless, because the receiver restarts its timing at every start bit. Inside one byte, though, the error adds up over ten bits, and at the last bit the receiver may read the wrong one. The datasheet recommends no more than about 2%.

| Baud Rate | UBRR (16 MHz) | Actual Baud | Error |
|-----------|---------------|-------------|-------|
| 2400 | 416 | 2398 | 0.08% |
| 9600 | 103 | 9615 | 0.16% |
| 19200 | 51 | 19231 | 0.16% |
| 38400 | 25 | 38462 | 0.16% |
| 57600 | 16 | 58824 | 2.1% |
| 115200 | 8 | 111111 | 3.5% |

:::caution
At 115200 baud with a 16 MHz crystal, the baud rate error is 3.5%. This is at the limit, and some USB-serial adapters then report framing errors (a stop bit that reads low). Use 9600 or 19200 for reliable communication, or enable double-speed mode (U2X0 = 1, $\text{UBRR} = F_{\text{CPU}} / (8 \times \text{BAUD}) - 1$), which lowers the error to 2.1% at 115200 baud (UBRR = 16) and to 0.8% at 57600 baud (UBRR = 34).
:::

## UART Initialization

<InArticleAd />


Setting up the UART is three writes: the baud rate, the switches for the transmitter and the receiver, and the frame format. The macro `UBRR_VAL` is the formula above. The compiler calculates it with whole numbers, so 103.17 becomes 103. It divides before it subtracts 1, so it always rounds down: at 115200 baud it gives 7, not the 8 of the table, which is 125,000 baud, 8.5% fast. For fast rates, work out the nearest whole number by hand.

```c
#define F_CPU 16000000UL
#define BAUD 9600
#define UBRR_VAL ((F_CPU / (16UL * BAUD)) - 1)

static void uart_init(void)
{
    /* Set baud rate */
    UBRR0H = (uint8_t)(UBRR_VAL >> 8);
    UBRR0L = (uint8_t)(UBRR_VAL);

    /* Enable transmitter and receiver */
    UCSR0B = (1 << TXEN0) | (1 << RXEN0);

    /* Frame format: 8 data bits, no parity, 1 stop bit (8N1) */
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);
}
```

## Blocking Transmit and Receive

<InArticleAd />


The transmitter sends one byte at a time, about 1 ms each at 9600 baud, so before each write to `UDR0` the code waits until the flag UDRE0 shows that the register is free. Waiting in a loop is called blocking, because the program does nothing else meanwhile: a line of 30 characters holds it for about 31 ms.

```c
static void uart_putc(char c)
{
    while (!(UCSR0A & (1 << UDRE0)));  /* Wait for empty buffer */
    UDR0 = c;
}

static char uart_getc(void)
{
    while (!(UCSR0A & (1 << RXC0)));   /* Wait for data */
    return UDR0;
}

static void uart_puts(const char *s)
{
    while (*s) uart_putc(*s++);
}
```

## Ring Buffer for Non-Blocking TX

<InArticleAd />


The logger sends one short line a second, so the complete firmware uses blocking transmit. When a main loop cannot wait, use a ring buffer, which works as a queue at a counter: the main code puts characters at the back and continues at once, and an interrupt takes one from the front each time the transmitter is free. The queue is an array with two positions: `head`, where the main code writes next, and `tail`, where the ISR reads next.

```text
  +---+---+---+---+---+---+---+---+
  | A | B | C | D |   |   |   |   |
  +---+---+---+---+---+---+---+---+
    ^               ^
    tail            head
    (ISR reads      (main writes
     next byte)      next byte)
```

After the ISR has sent 'A' and the main code has written 'E', both positions have moved one place. At the end of the array each returns to the start, which gives the ring its name.

```text
  +---+---+---+---+---+---+---+---+
  |   | B | C | D | E |   |   |   |
  +---+---+---+---+---+---+---+---+
        ^               ^
        tail            head
```

`tx_enqueue()` stores a character and switches on the UDRE interrupt, which fires whenever the transmitter can take a byte. The ISR sends one byte, and switches itself off when `head` equals `tail`: the queue is empty. If the queue is full, `tx_enqueue()` waits for a free place.

```c
#define TX_BUF_SIZE 64

static volatile char    tx_buf[TX_BUF_SIZE];
static volatile uint8_t tx_head = 0;
static volatile uint8_t tx_tail = 0;

static void tx_enqueue(char c)
{
    uint8_t next = (tx_head + 1) % TX_BUF_SIZE;
    while (next == tx_tail);  /* Wait if buffer full */
    tx_buf[tx_head] = c;
    tx_head = next;
    UCSR0B |= (1 << UDRIE0);  /* Enable UDRE interrupt */
}

ISR(USART_UDRE_vect)
{
    if (tx_head != tx_tail) {
        UDR0 = tx_buf[tx_tail];
        tx_tail = (tx_tail + 1) % TX_BUF_SIZE;
    } else {
        UCSR0B &= ~(1 << UDRIE0);  /* Buffer empty, disable interrupt */
    }
}

static void tx_puts(const char *s)
{
    while (*s) tx_enqueue(*s++);
}
```

## NTC Thermistor Circuit

<InArticleAd />


The ADC measures voltage, not resistance, so the thermistor goes in series with a fixed 10K resistor across the 5 V supply. The two share the voltage in proportion to their resistances (a voltage divider), and the ADC reads the point between them. When the thermistor warms, its resistance falls and the voltage at the ADC pin rises.

```text
         VCC (5V)
          |
        [NTC]  10K at 25C
          |    (resistance drops
          +--- as temp rises)
          |
  ADC0 ---+---> to ATmega328P PC0
          |
        [R1]  10K fixed
          |
         GND
```

![Wiring on an Arduino Nano: the thermistor from 5V to A0, and a 10K resistor from A0 to GND](https://cdn.siliconwit.com/education/embedded-programming-atmega328p/Nano-Thermistor-UART.png)

The firmware goes from the ADC number to a temperature in two steps.

First, the resistance. The voltage at the ADC pin is $V_{\text{adc}} = V_{CC} \times R_{\text{fixed}} / (R_{\text{therm}} + R_{\text{fixed}})$. The 10-bit ADC divides the range 0 to VCC into 1024 steps, so the reading is $\text{adc} = 1024 \times R_{\text{fixed}} / (R_{\text{therm}} + R_{\text{fixed}})$. Solving for $R_{\text{therm}}$:

```
R_therm = R_fixed * (1024 - adc) / adc
```

### Steinhart-Hart B-Parameter Equation

Second, the temperature. The resistance of a thermistor does not fall in a straight line with temperature, so the conversion needs a logarithm. This short form of the Steinhart-Hart equation is accurate enough near room temperature:

```
1/T = 1/T0 + (1/B) * ln(R/R0)
```

$T$ is the temperature in kelvin (degrees Celsius plus 273.15), $R$ is the thermistor resistance in ohms, and ln is the natural logarithm. $R_0 = 10\,000\,\Omega$ is the resistance at $T_0 = 298.15\,\text{K}$ (25 C), and $B = 3950$ comes from the thermistor datasheet.

For example, a reading of 600 gives $R = 10\,000 \times (1024 - 600) / 600 = 7067\,\Omega$, and then $T = 306.2\,\text{K}$, which is 33.0 C. A reading of 512, half of the range, means the two resistances are equal: 10,000 ohms, 25.0 C.

## Complete Firmware

<InArticleAd />


```c
#define F_CPU 16000000UL
#define BAUD 9600
#define UBRR_VAL ((F_CPU / (16UL * BAUD)) - 1)

#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/delay.h>
#include <util/atomic.h>
#include <stdlib.h>
#include <math.h>

/* --- UART (blocking for simplicity) --- */
static void uart_init(void)
{
    UBRR0H = (uint8_t)(UBRR_VAL >> 8);
    UBRR0L = (uint8_t)(UBRR_VAL);
    UCSR0B = (1 << TXEN0);
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);
}

static void uart_putc(char c)
{
    while (!(UCSR0A & (1 << UDRE0)));
    UDR0 = c;
}

static void uart_puts(const char *s)
{
    while (*s) uart_putc(*s++);
}

static void uart_putu16(uint16_t val)
{
    char buf[6];
    utoa(val, buf, 10);
    uart_puts(buf);
}

static void uart_putu32(uint32_t val)
{
    char buf[11];
    ultoa(val, buf, 10);
    uart_puts(buf);
}

/* --- ADC --- */
static void adc_init(void)
{
    ADMUX  = (1 << REFS0);  /* AVcc reference, channel 0 */
    ADCSRA = (1 << ADEN) | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);
    /* ADC enabled, prescaler 128 (125 kHz ADC clock) */
}

static uint16_t adc_read(void)
{
    ADCSRA |= (1 << ADSC);          /* Start conversion */
    while (ADCSRA & (1 << ADSC));   /* Wait for completion */
    return ADC;
}

/* --- Timer for timestamps --- */
volatile uint32_t ms_ticks = 0;

ISR(TIMER1_COMPA_vect)
{
    ms_ticks++;
}

static void timer1_init(void)
{
    TCCR1A = 0;
    TCCR1B = (1 << WGM12) | (1 << CS11) | (1 << CS10);
    OCR1A  = 249;
    TIMSK1 = (1 << OCIE1A);
}

static uint32_t get_ms(void)
{
    uint32_t val;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
        val = ms_ticks;
    }
    return val;
}

/* --- Temperature conversion --- */
#define B_COEFF  3950.0
#define T0_K     298.15
#define R0       10000.0
#define R_FIXED  10000.0

static int16_t adc_to_temp_x10(uint16_t adc_val)
{
    if (adc_val == 0) adc_val = 1;  /* Avoid division by zero */

    double r_therm = R_FIXED * (1024.0 - adc_val) / adc_val;
    double t_kelvin = 1.0 / ((1.0 / T0_K) + (log(r_therm / R0) / B_COEFF));
    double t_celsius = t_kelvin - 273.15;

    return (int16_t)(t_celsius * 10);  /* Fixed-point: 25.3C = 253 */
}

/* --- Main --- */
int main(void)
{
    uart_init();
    adc_init();
    timer1_init();
    sei();

    /* CSV header */
    uart_puts("timestamp_ms,adc_raw,temp_c\r\n");

    uint32_t next_sample = 0;

    while (1) {
        uint32_t now = get_ms();
        if (now >= next_sample) {
            next_sample = now + 1000;  /* 1 Hz sample rate */

            uint16_t adc_val = adc_read();
            int16_t temp_x10 = adc_to_temp_x10(adc_val);

            /* timestamp */
            uart_putu32(now);
            uart_putc(',');

            /* raw ADC */
            uart_putu16(adc_val);
            uart_putc(',');

            /* temperature with one decimal place */
            int16_t whole = temp_x10 / 10;
            int16_t frac  = temp_x10 % 10;
            if (frac < 0) frac = -frac;
            if (temp_x10 < 0 && whole == 0) uart_putc('-');
            char buf[8];
            itoa(whole, buf, 10);
            uart_puts(buf);
            uart_putc('.');
            itoa(frac, buf, 10);
            uart_puts(buf);

            uart_puts("\r\n");
        }
    }
}
```

## Summary

<InArticleAd />


A UART sends each byte as a start bit, eight data bits and a stop bit, with no clock wire, so both ends must use the same baud rate within about 2%. You set the rate with UBRR and write a byte to UDR0 when the flag UDRE0 is set. Blocking transmit is enough for a slow logger, and a ring buffer keeps a busy main loop free. From here on, text over the UART is your main tool for finding faults.
