A sensor sits still on the bench, and the number your program reads from it jumps between 507 and 516. Or the number is steady, but nobody can say what voltage it means. Both problems come from the ADC (analog-to-digital converter), the part of the ATmega328P that turns a voltage into a whole number from 0 to 1023. This lesson shows what that number means and how to make it steady. The project shows the light on two sensors as two bars on the OLED display. #ADC #AnalogSignals #Photoresistor

## ADC Register Overview

<InArticleAd />


A digital pin can only tell high from low, but a light sensor gives every voltage in between, so the chip needs a ruler for voltage: the ADC. It has 1024 marks, numbered 0 to 1023, spread evenly from 0 V up to a voltage you choose, the reference, and it returns the mark just below the input.

The one ADC is shared by several pins. A switch called the multiplexer (MUX) connects one pin at a time, and a small capacitor holds a sample of that voltage still while it is measured.

```text
  The path of one reading:

  ADC0 (PC0) --+
  ADC1 (PC1) --+    +--------+    +----------+
  ADC2 (PC2) --+--->|  MUX   |--->|  sample  |
  ADC3 (PC3) --+    | picks  |    | and hold |
  ADC4 (PC4) --+    | 1 pin  |    +----+-----+
  ADC5 (PC5) --+    +--------+         |
                                       v
                                +-------------+
                                |   10-bit    |
                                |  converter  |
                                +------+------+
                                       |
                                       v
                                result 0 to 1023
```

The converter finds the number by successive approximation, a guessing game played in halves. With a 5 V reference and 3.2 V at the pin, it tries 2.5 V (the input is higher: keep that half), then 3.75 V (lower: drop that quarter). Each try gives one bit; after 10 tries the result is 655.

So a reading needs three answers, each a group of bits in a register: which pin, against what reference, and how fast the tries run.

| Register | Purpose |
|----------|---------|
| ADMUX | Reference selection (REFS1:0), left-adjust (ADLAR), channel selection (MUX3:0) |
| ADCSRA | Enable (ADEN), start (ADSC), auto-trigger (ADATE), interrupt (ADIE), prescaler (ADPS2:0) |
| ADCSRB | Auto-trigger source (ADTS2:0) |
| ADCL/ADCH | 10-bit result (read ADCL first, or use ADC macro) |

ADC6 and ADC7 exist only on surface-mount packages.

### Reference Voltage Options

The reference is the top of the ruler, so the same input gives a different number against a different reference: 1.0 V reads 204 against 5 V, and 930 against 1.1 V. A small signal is measured more finely against a small reference.

| REFS1 | REFS0 | Reference | Typical Use |
|-------|-------|-----------|-------------|
| 0 | 0 | AREF pin (external) | Precision reference IC |
| 0 | 1 | AVcc with cap on AREF | General purpose (5V) |
| 1 | 1 | Internal 1.1V | Small signals, battery monitoring |

AVcc is the supply pin of the analog part of the chip: 5 V on the Nano and Uno.

:::caution
Never apply a voltage higher than the selected reference to an ADC pin. With AVcc reference (5V), input must be 0 to 5V. With the internal 1.1V reference, input must be 0 to 1.1V. Exceeding the reference voltage gives a reading of 1023, and a voltage above VCC can damage the pin.
:::

### ADC Clock and Prescaler

Each try needs time for the voltages inside the converter to settle; if the tries come too fast, the last bits are wrong. So the ADC has its own slow clock, the system clock divided by a prescaler.

For full 10-bit resolution that clock must be between 50 kHz and 200 kHz. With a 16 MHz system clock, prescaler 128 gives $16\,\text{MHz} / 128 = 125\,\text{kHz}$. One conversion takes 13 ADC clock cycles (25 for the first one after enabling), so a reading takes $13 / 125\,\text{kHz} = 104$ microseconds.

| ADPS2:0 | Prescaler | ADC Clock (16 MHz) | Conversion Time |
|---------|-----------|--------------------|-----------------|
| 000 | 2 | 8 MHz | Too fast |
| 011 | 8 | 2 MHz | Too fast |
| 101 | 32 | 500 kHz | Reduced accuracy |
| 110 | 64 | 250 kHz | Acceptable |
| 111 | 128 | 125 kHz | Best accuracy |

## ADC Driver Implementation

<InArticleAd />


`adc_init()` answers the three questions once. `adc_read()` selects a pin, starts a conversion by writing 1 to the ADSC bit, and waits. The hardware sets ADSC back to 0 when the result is ready.

```c
#define F_CPU 16000000UL
#include <avr/io.h>

static void adc_init(void)
{
    /* AVcc reference, right-adjusted result */
    ADMUX = (1 << REFS0);

    /* Enable ADC, prescaler 128 (125 kHz ADC clock) */
    ADCSRA = (1 << ADEN) | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);

    /* First conversion (25 clock cycles, discard result) */
    ADCSRA |= (1 << ADSC);
    /* Wait: the hardware clears ADSC when done */
    while (ADCSRA & (1 << ADSC));
}

static uint16_t adc_read(uint8_t channel)
{
    /* Select channel (clear old, set new) */
    ADMUX = (ADMUX & 0xF0) | (channel & 0x0F);

    /* Start conversion */
    ADCSRA |= (1 << ADSC);
    while (ADCSRA & (1 << ADSC));

    return ADC;  /* Read 10-bit result */
}
```

## Free-Running Mode

<InArticleAd />


The driver above stops the program for 104 microseconds at every reading. In free-running mode the ADC starts a new conversion by itself as soon as the last one ends, and the program reads the newest result with no wait. Enable it by setting ADATE (auto-trigger enable) in ADCSRA and selecting free-running as the trigger source in ADCSRB (ADTS2:0 = 000). The ADC then stays on one pin. This project reads two pins in turn, so it uses single conversions.

```c
static void adc_init_freerun(uint8_t channel)
{
    ADMUX  = (1 << REFS0) | (channel & 0x0F);
    ADCSRA = (1 << ADEN) | (1 << ADSC) | (1 << ADATE)
           | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);
    ADCSRB = 0;  /* Free-running trigger source */
}

/* Read the latest result (non-blocking) */
static uint16_t adc_read_freerun(void)
{
    return ADC;
}
```

## Oversampling for Noise Reduction

<InArticleAd />


ADC readings are noisy, especially on a breadboard with long wires and a USB supply: the input does not move, but each reading lands a few steps above or below the true value. Oversampling takes extra readings and averages them, so the errors above and below cancel.

```text
  Effect of oversampling (16 samples):

  Raw samples (noisy):
  512 508 515 510 513 507 514 511
  509 516 510 512 508 513 511 510

  Average: 511 (clean)
```

Random noise falls by the square root of the number of samples, not by the number itself: 16 samples make it 4 times smaller, worth about 2 extra bits. The cost is time: 16 conversions take $16 \times 104\,\mu\text{s} \approx 1.7$ milliseconds. An error that is the same in every reading, such as a wrong reference voltage, stays in the average.

```c
#define OVERSAMPLE_COUNT 16

static uint16_t adc_read_averaged(uint8_t channel)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < OVERSAMPLE_COUNT; i++) {
        sum += adc_read(channel);
    }
    return (uint16_t)(sum / OVERSAMPLE_COUNT);
}
```

## LDR Voltage Divider Circuit

<InArticleAd />


The ADC measures voltage, but an LDR changes its resistance. A voltage divider turns one into the other: two resistors in series share the supply in proportion to their resistances, and the ADC pin reads the point between them. Each LDR is paired with a fixed 10K resistor.

```text
  Dual LDR circuit:

       VCC            VCC
        |              |
      [LDR]          [LDR]
      Left           Right
        |              |
  PC0 --+         PC1--+
  (ADC0) |        (ADC1)|
        |              |
      [10K]          [10K]
        |              |
       GND            GND

  Bright light: LDR low R, high V at ADC
  Darkness:     LDR high R, low V at ADC
```

The LDR connects from the ADC pin to VCC, and the 10K resistor from the ADC pin to ground: a [voltage divider](/education/analog-electronics/voltage-current-resistance/). The pin voltage is the share of VCC across the lower resistor:

$$
V_{\text{pin}} = V_{CC} \times \frac{10\,\text{k}\Omega}{R_{\text{LDR}} + 10\,\text{k}\Omega}
$$

In bright light the LDR falls to about 1K: $5 \times 10 / 11 = 4.55$ V, which reads 930. In the dark it rises to about 100K: $5 \times 10 / 110 = 0.45$ V, which reads 93. So more light gives a larger number. The left LDR is on PC0 (ADC0, Arduino pin A0) and the right one on PC1 (ADC1, pin A1).

![Wiring drawing: each LDR goes from 5V to pin A0 or A1, and each 10K resistor from that pin to GND. The OLED keeps its SPI wires.](https://cdn.siliconwit.com/education/embedded-programming-atmega328p/Nano-LDR-OLED-ADC.png)

### ADC Value to Voltage Conversion

To turn a reading back into a voltage, multiply it by the size of one step, which is the reference divided by the 1024 steps:

```
V = (ADC_value / 1024.0) * V_ref
```

For AVcc reference (5V): an ADC reading of 512 corresponds to 2.5V, and one step (1 LSB) is $5\,\text{V} / 1024 \approx 4.9\,\text{mV}$. Divide by 1024, the number of steps, not by 1023, the largest reading.

## Complete Firmware

<InArticleAd />


Each pass of the loop reads both LDRs, scales each reading to a bar of 0 to 50 pixels, and draws the bars with the display code from the SPI lesson. The arrow changes only when the readings differ by more than 50, so it does not flicker when both sides are almost equal.

```c
#define F_CPU 16000000UL

#include <avr/io.h>
#include <util/delay.h>
#include <stdlib.h>
#include <string.h>

/* From Lesson 6: framebuf[], spi_init(), oled_init(), oled_flush(),
   fb_clear(), fb_draw_char(), fb_draw_string() */

#define OVERSAMPLE 16
#define BAR_MAX_WIDTH 50  /* pixels per bar */

static void adc_init(void)
{
    ADMUX = (1 << REFS0);
    ADCSRA = (1 << ADEN) | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);
    ADCSRA |= (1 << ADSC);
    while (ADCSRA & (1 << ADSC));
}

static uint16_t adc_read(uint8_t channel)
{
    ADMUX = (ADMUX & 0xF0) | (channel & 0x0F);
    ADCSRA |= (1 << ADSC);
    while (ADCSRA & (1 << ADSC));
    return ADC;
}

static uint16_t adc_read_avg(uint8_t ch)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < OVERSAMPLE; i++) sum += adc_read(ch);
    return (uint16_t)(sum / OVERSAMPLE);
}

/* Draw a horizontal bar at (col, page) with given width */
static void fb_draw_bar(uint8_t col, uint8_t page, uint8_t width)
{
    uint16_t offset = page * 128 + col;
    for (uint8_t i = 0; i < width && (offset + i) < 1024; i++) {
        framebuf[offset + i] = 0x7E;  /* Solid bar pattern */
    }
}

/* Draw a simple arrow character */
static void fb_draw_arrow(uint8_t col, uint8_t page, char dir)
{
    uint16_t offset = page * 128 + col;
    if (dir == '<') {
        uint8_t arrow[] = {0x08, 0x1C, 0x1C, 0x3E, 0x3E, 0x7F, 0x7F};
        for (uint8_t i = 0; i < 7 && (offset+i) < 1024; i++)
            framebuf[offset + i] = arrow[i];
    } else if (dir == '>') {
        uint8_t arrow[] = {0x08, 0x1C, 0x1C, 0x3E, 0x3E, 0x7F, 0x7F};
        for (uint8_t i = 0; i < 7 && (offset+i) < 1024; i++)
            framebuf[offset + i] = arrow[6 - i];
    } else {
        uint8_t eq[] = {0x00, 0x24, 0x24, 0x24, 0x24, 0x24, 0x00};
        for (uint8_t i = 0; i < 7 && (offset+i) < 1024; i++)
            framebuf[offset + i] = eq[i];
    }
}

int main(void)
{
    spi_init();
    oled_init();
    adc_init();

    while (1) {
        uint16_t left  = adc_read_avg(0);
        uint16_t right = adc_read_avg(1);

        /* Scale to bar width */
        uint8_t bar_l = (uint8_t)((uint32_t)left  * BAR_MAX_WIDTH / 1023);
        uint8_t bar_r = (uint8_t)((uint32_t)right * BAR_MAX_WIDTH / 1023);

        fb_clear();

        /* Labels: the Lesson 6 font holds only digits and ':'.
           Add glyphs for these letters to font_5x7 and
           fb_draw_char(), or these two calls draw nothing. */
        fb_draw_string(0, 0, "LEFT");
        fb_draw_string(90, 0, "RIGHT");

        /* Bars */
        fb_draw_bar(0, 2, bar_l);
        fb_draw_bar(128 - bar_r, 4, bar_r);

        /* Direction arrow */
        char dir = '=';
        int16_t diff = (int16_t)left - (int16_t)right;
        if (diff > 50) dir = '<';       /* Left is brighter */
        else if (diff < -50) dir = '>';  /* Right is brighter */
        fb_draw_arrow(60, 6, dir);

        /* Numeric values */
        char buf[5];
        utoa(left, buf, 10);
        fb_draw_string(30, 0, buf);
        utoa(right, buf, 10);
        fb_draw_string(70, 0, buf);

        oled_flush();
        _delay_ms(50);  /* ~20 Hz update */
    }
}
```

## ADC Noise Reduction Sleep Mode

<InArticleAd />


Part of the noise comes from the chip itself: the running processor disturbs the supply of the ADC. In ADC Noise Reduction sleep mode the processor stops for one conversion while the ADC keeps working, and its interrupt wakes the processor at the end. Use it when averaging alone does not give a steady reading.

```c
#include <avr/sleep.h>
#include <avr/interrupt.h>

ISR(ADC_vect)
{
    /* Conversion complete, CPU wakes up */
}

static uint16_t adc_read_quiet(uint8_t channel)
{
    ADMUX = (ADMUX & 0xF0) | (channel & 0x0F);
    ADCSRA |= (1 << ADIE);  /* Enable ADC interrupt */
    set_sleep_mode(SLEEP_MODE_ADC);
    sei();
    sleep_mode();            /* Enter sleep, ADC starts automatically */
    ADCSRA &= ~(1 << ADIE); /* Disable ADC interrupt */
    return ADC;
}
```

:::tip[Instrument it]
The ADC is your bridge to the analog machine. The same code that reads an LDR reads the sensors that report a motor's health: an NTC thermistor on the winding for temperature, an ACS712 or a shunt-plus-amplifier on the supply for current, and a vibration sensor for mechanical trouble. Watching current and temperature together is the cheapest motor monitor there is, since a rising pair means a bearing dragging or a fan failing. An [ATmega](/education/sensor-actuator-interfacing-stm32/) reads them, and through an [ESP32 or STM32 link](/education/iot-systems/) can [alert before the motor burns out](https://siliconwit.io).
:::

3. Stream the raw ADC values over UART (with the driver from the serial communication lesson) at 100 Hz and plot them in real time using a serial plotter or Python script. Observe the noise with and without averaging.
4. Implement a simple peak detector: track and display the maximum ADC reading seen since the last reset (button press clears the peak).

## Summary

<InArticleAd />


An ADC reading is a fraction of the reference voltage, counted in 1024 steps. Three settings decide it: the pin, the reference and the ADC clock (50 kHz to 200 kHz). Averaging N readings makes random noise smaller by the square root of N.
